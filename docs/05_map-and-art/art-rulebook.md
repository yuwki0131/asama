# アートルールブック(ビジュアルQAゲート判定基準)

ユーザーフィードバックから抽出した**チェック可能なルール**の集約。各ルールはID付きで、
L1(機械lint: `assets:lint:art`)または L2(VLMセルフレビュー)のどちらで検証するかを明記する。

運用原則: **一度指摘されたことは二度とユーザーに指摘させない。**
指摘→修正のサイクルは、該当ルールをここに1行追加してからクローズする(→ [PROC-01])。

様式語彙(ペインタリー、植生様式シート、品質標準)は `art-direction.md` が正。
本書はそれを「合否判定できる文」に変換したチェックリストである。

## GEO: 幾何契約(L1機械検査)

| ID | ルール | 検証 |
|---|---|---|
| GEO-01 | 建物アンカーは族別幾何契約に従う(レンダラーのピン位置準拠): 標準建物ロット=H-32(`anchorRow=height-32`、非正方フットプリントは `anchorX=width/2+(fw-fh)*16` の半タイルオフセット)/ 接地タイルキット(道・柵・塀・本丸マーカー・deco)=`height-16` / 堀=上端から16px(掘り込みは下方向に延長)/ 門=`height-8-(n+1)*8`(n=セル数)/ 橋=材質定数(土24px・木32px、下端から)/ 平地ロット(田)=キャンバス中心かつ `width=2*height` | L1: manifest全件照合 |
| GEO-02 | 地形面アセット(cliff/ishigaki face・corner)はキャンバス `64×(32+40h)`、アンカー `(0.5, 16/(32+40h))` | L1: manifest照合 |
| GEO-03 | 面アセットの**壁上端はセル辺に一致**すること: 上端行(y16〜24)の不透過x範囲が e面=右半分(x≥32)/ s面=左半分(x≤32)に収まり、辺からのドリフト≤2px。裾の反り出しは合計≤13px(石垣sori上限0.40 world units) | L1: 行ごと不透過x範囲走査 |
| GEO-04 | オートタイルファミリ(橋・川岸・道等)はタイル境界1px列の色シグネチャが隣接バリアント間で連続すること | L1: 境界列比較 |
| GEO-05 | 基壇・砂利パッドはフットプリント菱形と幾何学的に一致(はみ出し・不足なし) | L1: bbox/菱形適合 + コンタクトシート |
| GEO-06 | アニメシートは列=フレーム、行=方向。フレーム間でアンカーの重心ドリフトなし | L1 |
| GEO-07 | 描画順: 隣接建物のスプライトが他建物の屋根庇を上書き(見切れ)しないこと。等深度(maxX+maxY同値)のフットプリントは物理的に遮蔽し得ないため、庇の張り出しが大きいもの(面積大)を後描きする | renderGeometry.test.ts回帰 + L2目視(拡大時の庇連続性) |

## VAR: バリアント実効差分(L1機械検査)

| ID | ルール | 検証 |
|---|---|---|
| VAR-01 | バリアントプール(`<base>.p<n>` / `<base>.v<n>` 形式でbase assetIdがマニフェストに存在するもの)の各メンバーは、baseとの**meanAbsDiff(相互不透過画素の3ch絶対差合計平均)が12以上**であること。プールが存在してもメンバーが画素同一なら反復対策機構は空回りし、COMP-03(REP)はassetIdの直線ランしか見ないため検出できない(堀・川のp1-p3が実測8-13で実質同一だったV-01事故のブラインドスポット)。真に差があるプールはtown_blockで99+、事故帯は5-15。既存のサブ可視ペア(terrain.water/grass/dirtのv系など静的レジストリ側)はルール例外ではなく `art-lint-baseline.json` に既知違反として記録 — 新規バリアントは床値を満たすこと | L1: `assets:lint:art` |
| VAR-02 | **可視帯で差をつける**: バリアントの差分は、そのアセットが実マップで露出する画素帯に置くこと。密集列では手前の建物が胴体を遮蔽し**屋根+妻面しか見えない**ため、壁・庭だけを変えたバリアントはmeanAbsDiffが大きくても列は同一に読める(V-04: machiya v1/v2は差分83-140だったが屋根が同一瓦マテリアルで列の反復感が残存 — v2屋根を風化瓦+木製ケラバに分岐して解消)。密集列ファミリは屋根マテリアル/妻面から差をつける | L2: 実マップビューで確認 |
| VAR-03 | **等ピッチ列の選択は循環式**: 一定ピッチで並ぶ建物ファミリ(machiya 2セル、samurai_residence 8セル)のバリアント選択は純ハッシュではなく**位置循環+行毎位相**(x/pitch mod n、行位相は1..n-1のステップで累進し隣接行の同一シーケンス化も防ぐ)にすること。純ハッシュは隣接同一ペアを確率的に残す(V-04初版レビューで指摘)。プールが小さい(n=3)ほど必須 | 単体テスト(隣接非同一) |

## COMP: コンポジット整合(マップスケールL1機械検査)

アセット単体lintでは検出できない**組み合わせ時の欠陥**を、実ゲーム画面の標準6ビュー
(`assets/definitions/composite-views.json`: first/center/nw/ne/sw/se)を撮影して機械検査する。
実行: `node qa/composite-lint.mjs --scenario <name>`(apps/game、dev server起動が前提)。
レポート/スクリーンショットは `artifacts/composite-lint/<scenario>/` に出力。

| ID | ルール | 検証 |
|---|---|---|
| COMP-01 | **穴あき空間(GAP)禁止**: スプライト間の隙間から背景が透けないこと。クロマキー(マゼンタclear+地形アンダーレイ非表示のdebugChromaMode)で背景露出画素を検出し、連結成分≥24px(セル辺シームは≥220px)をerror。典型原因は異種ピース(斜面側壁↔崖面)の凹接合で双方のアートが契約ポリゴンから後退するくさび隙間 — 対策はシーン最下層の契約クアッドバックドロップ(terrainLayer `addElevationBackdrops`) | L1: composite-lint GAP |
| COMP-02 | **黒穴・白飛び(VAL)禁止**: 合成結果に極端輝度の厚い連結領域を作らないこと。暗側はsum(r+g+b)<90を1px侵食(erode-1)後、連結成分≥2500pxをerror(1-2pxのペインタリー輪郭線・陰影シームは侵食で落ち、真の黒穴のみ残る)。明側はsum>705同様。暗側の「暗いが黒ではない」アセットはLUM-01(アセット単体)の管轄 — COMP-02は合成起因の黒穴(背景露出・未照明フィル)専用 | L1: composite-lint VAL |
| COMP-03 | **繰り返し感(REP)抑制**: 同一assetIdの直線連続ラン(x/y方向)を計測し、バリアントプール保有ファミリでの長ラン(プールがあるのに使われていない)をerror、プール未整備ファミリはinfoに留める。塀(wall.plaster.connected)・道(road.connected)の直線辺は位相バリアントプール(p1-p3、分離レジストリwallroad)整備済みでerror対象ファミリに昇格(V-05解消、旧info負債)。直線マスク以外(角・T字・交差)は連鎖しないため単一スプライトのまま | L1: composite-lint REP |

## EDGE: マップ外周(マップスケールL1機械検査)

マップの端は「世界がそこで途切れる」のではなく「世界が続いているが見えなくなる」と読めること(パトロール台帳V-02)。
実装契約は2点: (1)シミュレーションのautotileはマップ外隣接を**同種地形**として扱う(`connectedTerrainAssetId`が汀・フリンジ縁をリムに描かせない — 旧実装はマップ外=異種扱いでリム全周に「別の端」に見える偽の縁取りを生成した)、(2)レンダラは外周スカート(リム地形を12リング分続けるpseudo-cell群+背景色キャンバスグラデーションのフェードオーバーレイ、terrainLayer `buildPerimeterSkirtCells`/`buildSkirtFadeOverlay`)で溶暗させる。

| ID | ルール | 検証 |
|---|---|---|
| EDGE-01 | **カミソリカット禁止**: リムセルから外向きレイ上で、地形レイヤ表示/非表示の2枚スクリーンショット差分(空気遠近ヘイズ等の上位合成を相殺し地形寄与のみを分離 — 単一背景色比較はヘイズ自身の減衰勾配を「フェード」と誤読する)が閾値(max-ch diff>10)を超える最遠距離=フェード到達距離のレイ中央値が**120px×zoom以上**であること。カミソリカットは〜1セル(18-36px、リムセルアートのはみ出しで最大〜96px)、12リングスカートは150px(コーナーz0.75)〜480px(直線辺z1)で、120は両域をマージン付きで分離。専用エッジビュー(composite-views.json `edgeViews`: 辺4+コーナー2、通常レンダー — クロマキーは半透明フェード自体をキーアウトしてしまうため不可)で計測 | L1: composite-lint EDGE |

## ELEV: 高低差エッジの判読性(L2レビューカード)

段丘エッジ(崖面・石垣面・斜面)は「地形の高低差」として読めること(パトロール台帳V-03)。
症状は合成起因(額縁化・上載建物との同化)のためL1機械検査への昇格は不可 — 狙い撃ちビュー
(`visual-patrol.mjs --cells`)+別コンテキストVLMレビューで検証する。

| ID | ルール |
|---|---|
| ELEV-01 | **額縁化禁止**: 崖天端が濃い平帯で草地を縁取らないこと。天端は上面の植生が面へ折り返す(連続ソッドリップ+タフト)+天端コースを明るい石にバイアスし、草→石の遷移を有機的に破る |
| ELEV-02 | **上載建物との同化禁止**: 石垣面とその上の塀・櫓基部が同色同テクスチャで連続しないこと。地形面は建物基部より明・暖側に保ち、明度階層で高低差を読ませる(石材パレットの明側引上げ+暖色化) |
| ELEV-03 | **接地感**: 崖下端に足元の苔帯・湿り石など接地記号を置く(段丘が浮いて見えることの防止)。水際(堀・川に落ちる面)はbank/rim系アセットの管轄(V-06) |
| ELEV-04 | **面の明度連続性**: 凸コーナーの左右面の明度差は隅石(quoin)で緩衝し、硬い縦シームを作らない。法線由来の陰面(E面)はパレット側で補償ブーストする |
| ELEV-05 | **斜面の誤読防止**: 石段・斜面ピースが屋根/庇に読めないこと(暗スラブの明度床と出現率を抑制、踏面の歩行線は明るく) |

## WTR: 水際・土手(L2レビューカード)

水域(堀・川・terrain水)の陸/水境界の描写標準(パトロール台帳V-06)。リム帯・ウォーター
ラインは数px幅の部分領域で全体luma平均に埋もれるためL1機械検査への昇格は不可(実効差分は
VAR-01、暗部はLUM-01の網でカバー)— 狙い撃ちビュー+別コンテキストVLMレビューで検証する。

| ID | ルール |
|---|---|
| WTR-01 | **リム帯のフラット単色禁止**: 陸/水境界のリム帯(草→bankの遷移帯)はノイズ破断されたランプ(暗土→乾土→草側オリーブ)で描き、外縁を隣接草にフェザリングする。フラット単色は遠景で黒帯(暗色時)or白茶け菱形階段(明色時)として反復読みされる。全水域ファミリ(trench moat/river・terrain shore)で同一の土手色言語を共有する |
| WTR-02 | **静水面のウォーターライン必須**: 水を湛える土手基部には破断された明ハイライト帯(低端=水面色に一致、幅≈0.055)を置き、bank暗部が直接水面に接する黒スリットを防ぐ。接地感(ELEV-03の水際側)もこれで担保する |
| WTR-03 | **watch**: ベースマスクのウォーターライン破断パターンはphase=(0,0)固定で64px周期反復あり。再発時はV-01方式(map-anchored位相場)で位相化する |

## 種別ルール(L2レビューカード)

### 田畑(FARM)

| ID | ルール |
|---|---|
| FARM-01 | 稲は**1px幅の線ストローク**を株元から扇状に立て先端を尖らせる。塗り潰し楕円・円形クランプ・「もこもこの塊」は禁止 |
| FARM-02 | 夏=緑の葉+明るいチップ、秋=穂が横下に垂れるが**線的質感を維持**(黄色い塊化禁止) |
| FARM-03 | 実際の稲の風景(夏秋の水田)を参照前提として判定する |
| FARM-04 | 実った水田の床は「日陰の藁ゴールド」であり土ではない。床と株のコントラストを低く保つ(高コントラストは塊/ドット読みを誘発しFARM-01違反に繋がる) |
| FARM-05 | 稲穂は閉じたキャノピーの上に**最上層として後描き**する: 連続した1pxアーチ(立ち上がり→垂れ)、田全体で風向バイアス(≈85%同方向)、穂ストロークにピクセルノイズを乗せない(ノイズはアーチを紙吹雪化させ判読性を殺す) |
| FARM-06 | 季節派生は元絵の近黒ピクセル(水際テクスチャ)を田内部に残さない(ゴールド地に黒コショウ斑となる)。畦のアウトライン黒は保持 |

### 狭間壁(HAZAMA)

### 斜め壁(DIAG)

| ID | ルール |
|---|---|
| DIAG-01 | 斜め壁は既存漆喰壁と同一のWALL_*寸法・材質セット(石基壇+漆喰胴+反り笠木)で構築し、同族に見えること。別素材・別高さの「新種の壁」に見える状態は不合格 |
| DIAG-02 | 同方向チェーン(nwse連続/nesw連続)はセル角で断面が一致しシームレス接続。隣接スプライト間に隙間・段差・重複による濃淡ムラが見える状態は不合格 |
| DIAG-03 | 画面縦ラン(nwse)は視線が棟と平行なため笠木上面が支配的な「濃い帯」になるのは幾何的に正。ただし笠木上面には垂木/瓦条のテクスチャが読めること(のっぺり単色は不合格) |
| DIAG-04 | 斜め壁⇔直線壁のジャンクションは接続アーム(直線壁セルの中心→角オーバーレイ、wall-diagonal-arm-{nw,ne,se,sw})で視覚的に連結すること。合流部に隙間・浮き・途切れが見える状態は不合格。アームは斜め壁の対角線がその角を通る場合のみ出現し(nwse=自セルNW+SE角、nesw=NE+SW角)、無関係な壁セルにアームが出るのも不合格 |
| DIAG-05 | アーム/斜め壁は壁スプライトより先に描画し、壁帯がアームの中心側切断面・笠木ハッチを隠すこと(壁上にアームの笠木稜線が乗る「ノイズ斑/スパイク」は不合格)。角で直交2セグメントのみが出会うエルボー(共線ペアなし)は角柱キャップ(building.wall.corner.cap、石基壇+漆喰柱+方形笠木)で未処理切断面を覆うこと。T字/十字/直進(共線ペアあり)にキャップが出るのは不合格。キャップは最前面参加セル(x+y最大、次にx最大)が自スプライト後に描画し、両壁より手前に見えること |
